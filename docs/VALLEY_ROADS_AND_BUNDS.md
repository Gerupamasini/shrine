# 谷底の農道・畦・運転入力の修正

PR #15を取り込んだmain `e3044d7` を基点とする。

## 道路配置

旧生成では川と県道のほぼ中間に縦道を置き、12本の横道を同じ方向に貫通させていた。谷の広がりと支谷の出口に応じて縦道の位置を変え、県道側7本と川側5本の支道をずらしたT字分岐で接続する。県道から川まで同じ横道が続く反復をなくす。既存屋敷の周囲では以前の通路を保ち、屋敷を移して新しい道路に合わせることはしない。生成の乱数列を変えないため、旧道路の予約範囲は家屋配置の段階にだけ残す。

水路の直線部分は排水の役割があるため維持する。農道の付け替えに伴い、沢の横断施設は新しい道路との実交点から作り直す。従来の縦道位置を使うと、道路の移動先に開渠が残り車が落ち込むことを高さ検査で確認した。屋敷林を含む全樹種も新しい農道から離す。

前回調査した[林野庁の森林作業道指針](https://www.rinya.maff.go.jp/kinki/seibi/romou_seibi/6_.html)と[姨捨の棚田資料](https://www.city.chikuma.lg.jp/soshiki/rekishibunkazaicenter/rekishi_bunkazai/2/2375.html)を継続参照。今回の谷底線形は、このゲームの地形と既存屋敷に合わせた設計であり、実在の集落をそのまま複製したものではない。

## 田面が浮いて見える問題

- 元の解析的な区画線だけでなく、切り詰め・分割後の実際の区画外周にも畦を生成する。
- 畦の頂部は隣接する高い田面を基準に34cm上げる。稲の描画開始位置は境界から1.65m内側とし、畦の土が見える余地を確保する。
- 後段の河岸・路肩整形が畦を削らないよう、給排水口以外の区画地形を保護する。最終的な16bit地形で田面より低い外周が残らないことを生成時に検査する。
- 耕作地を含む地形チャンクでは遠景でも元の頂点間隔を維持する。従来の4倍・8倍間隔では畦だけが省略され、別描画の稲の面が地面から離れて見えていた。
- 稲の縁の側面は最寄りの田面高を使う。近隣の高い棚田の標高を拾って下段の側面が持ち上がる処理を修正する。

これは畦・田面・稲の描画の整合性の修正であり、新しい水理シミュレーションの追加ではない。細い棚田の平坦部を確保する既存検査も維持する。

## 運転の左右

入力は右を+1としていたが、車の前方がローカル+Zであるため、+Y回転は運転者から見て左になる。入力から物理操舵角への符号を修正した。以前のテストも世界座標の-Xを単純に「左」としていたため、運転者の向きに対する左右で検証するよう改めた。実際のA/D・左右矢印キーを使い、運転席・後方視点の双方で車の進行方向を確認する。

## 再生成と検証

生成は `python3 tools/world/generate_world.py`、道路構造物は `node tools/architecture/build.mjs --world-only`、地図は `python3 tools/world/bake_map.py`。

Pythonの検査は `tests/rural.test.py`、`tests/irrigation.test.py`、`tests/paddy-bunds.test.py`、`tests/valley-roads.test.py`。データ・物理検査は `npm test`、ビルドは `npm run build`。

変更前後は `artifacts/valley-before/` と `artifacts/valley-after/`。地上・遠景比較は保存した同一カメラ位置・時刻で撮影する。谷底全13区間の車両検証は `VALLEY_DRIVE=1 CHROMIUM_PATH=/usr/bin/chromium npx playwright test tests/rural-driving.spec.ts`。左右入力は `tests/steering-input.spec.ts`、既存3周回の歩行は `tests/rural.spec.ts`。

全水田への給排水の確定と歩行専用の畦道ネットワークは前回からの残課題。今回も未接続区画を給水済みとは扱わない。耕作地の地形を省略しない分、遠景で描く三角形は増える。

## 数値確認

- 谷底農道の総延長は2,883mから2,214m。県道から川まで貫く横道を減らし、田へ入る枝道へ置き換えた。
- 畦の確認点40,317点（水口・排水口の773点を除く）の最小高さは田面より0.3368m上。田面以下の閉じた外周は0点。
- 軽トラック7台、分校1棟、消防詰所1棟の位置・向き・縮尺はmainと一致。3周回の道路構成も一致。
- 集落の建物82件（施設を含む）の位置・向き・種類・バリエーションもmainと一致。
- 再区画後は588区画、棚田266区画、旧来型の不整形区画227区画。給水確認137区画、未確認365区画。変更前後の集計は `comparison.json`。
- 地形全1,600チャンクのうち耕作地に接する377チャンクで元の頂点間隔を保持する。
- Python7件、Node29件が成功。`npm run build` 成功（既存の大きいバンドルの警告あり）。

## 実走行での修正と記録

最初の谷底全13区間の検証では11区間を通過し、宮沢の水路に近すぎる入口と、南側の家屋を横切る枝道で停止した。宮沢の入口を水路から離し、南側の枝道を屋敷の北から接続するよう変更。関係する川側の枝道もずらし、変更した3区間を再検証して通過・停止を確認した。さらに、枝道→縦道→別の枝道へ連続して進む左右のT字旋回も確認した。

縦道の接続周辺では造成の高さが最大31cm変わったため、変更範囲を含む南北約410mを再走行した。その他の通過済み9区間と既存周回8区間では、線形と車道幅2.5m内の地表高の差が0。縦道も再走行範囲外では差が0である。

`artifacts/valley-after/driving.json` は初回の失敗2区間を含む記録、`driving-recheck.json` は修正3区間と連続旋回の成功記録、`spine-recheck.json` は縦道の再検証。`unchanged-road-check.json` は再生成前後の道路の照合結果。

初回ブラウザ実行の `browser-initial.json` は、既存運転と3周回両方向の歩行が成功し、上記の車両検査1件が失敗した記録。重複する左右キー・撮影テストは、別の最終版実行で確認するため途中で停止した（並列撮影で実行環境のメモリ使用量が上限に近づいた）。初回レポート全体が成功したとは扱わない。最終版の記録は `browser-recheck.json` と `browser-spine.json` に分けて保存する。

最終版の再検証は3件すべて成功（修正した農道・T字旋回、A/D・左右矢印の両視点、比較撮影）。縦道の再走行も1件成功した。地上の田、棚田、展望地点の最終画像を確認し、畦の土と田面・稲の縁がつながっていることを確認した。画像は `paddies.png`、`tanada.png`、`lookout.png`、運転席の左右確認は `steer-left.png` と `steer-right.png`。

再検証は `VALLEY_RECHECK=1 CHROMIUM_PATH=/usr/bin/chromium npx playwright test tests/rural-driving.spec.ts tests/steering-input.spec.ts tests/valley-views.spec.ts`。縦道の変更範囲は `VALLEY_DRIVE=1 VALLEY_SPINE_SECTION=1 RURAL_DRIVE_ROAD=farm-00 CHROMIUM_PATH=/usr/bin/chromium npx playwright test tests/rural-driving.spec.ts`。

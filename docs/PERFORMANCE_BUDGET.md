# 負荷予算と計測

**計測環境**：このリポジトリの開発環境にはGPUがありません。数値はSwiftShader（CPUでのWebGL2描画）を使い、`window.__satoyama.breakdown()` で集計した三角形数です。fpsは実GPUで計測していないため、60fpsの達成は**未確認**です。

> **注意（2026-11-12）**：地図を1.5km四方に広げ、山を浸食モデルに置き換えた後、下の内訳表は測り直していません。撮影時の合計は標準品質で約1,600万〜2,200万三角形（影の描画を含む）でした。測り直しは [HANDOFF.md](HANDOFF.md) のやり残しに入れています。
>
> **追記（2026-11-13）**：樹木は約6.3万本から約5.5万本に減り（林分ごとの植林・伐採跡）、遠景の稲の縁に株の帯（数十万三角形、影なし）を足しました。作業中の撮影では標準品質で約1,700万〜2,100万三角形でした。内訳表はまだ測り直していません。

煙（8本×32枚）ととんぼ（225匹×24三角形）は合わせて1万三角形未満です。

地図の外の森（遠景の木のビルボード）は、標準で約18万本（約37万三角形）、軽量で約6万本です。1回の描画で、毎フレームの処理はありません。

近景の稲は株の間隔を30cm・半径15mにしたため、田のそばでは上の表より約55万三角形増えます（約140万）。田から離れると描きません。

ミニマップと全体図は2Dキャンバスで、WebGLの描画には入りません。地図の画像（`map.webp`、2560²、約0.9MB）を読み込み、ミニマップは毎秒30回まで、全体図は開いている間だけ描き直します。

草と稲のインスタンスはカメラからの距離順に並んでいます。品質を下げると先頭のN個だけを描き、半径を縮めます（軽量0.68倍・標準0.88倍・高品質1.0倍）。密度が0の株も頂点処理の対象として数えています（ラスタライズはされません）。SSAOは半解像度の画面処理で、三角形は増えません。

## 主な最適化

- **樹木**：約4.1万本を、樹種×変種×LODごとのInstancedMeshで描く。距離・視錐台・影の判定は、カメラが動いたときだけ行う。
- **遠景の樹木**：起動時にLOD0から焼いたビルボード（アルベドと法線のアトラス）で、全樹木を1回の描画で描く。
- **地形**：37.5mのチャンクに分け、3段のLODとスカートで継ぎ目の隙間を隠す。法線は1025²の法線テクスチャで補うので、粗いLODでも陰影は細かい。
- **草・稲**：インスタンス格子をカメラに追従させ、密度0の株は頂点シェーダーで潰す。近景の稲はPoly Havenの写真の草株を稲の高さに拡大したもので、田に近いときだけ描く。中景は基底層と3層のシェル。
- **建築のGLB**：頂点を溶接し、KHR_mesh_quantizationで量子化（24MB→5.7MB）。
- **Poly Havenの小物・植物**：meshoptimizerで削減し、テクスチャを512²にしている。複数の個体が並んだ原本（シダ・低木・雑草・苔むした岩）は1個体ずつに分け、1回の配置で1個体だけを描く。

# 描画予算と計測方法

標準：デスクトップ1080p、60fps（GPU 16.7ms）、150万三角形、250 draw calls、テクスチャ256MiBを上限目安とする。これは保証値ではない。ソフトウェアWebGLの計測値から実機の60fpsを推測しない。

| 分野 | 三角形の目安 | 個別メッシュの上限目安 | 方法 |
|---|---:|---:|---|
| 地形・遠景 | 150,000 | 地形131,072 | 原本513²、描画257²。原本を削らない |
| 神社・家屋 | 350,000 | 神社20k、家屋8k | 材質単位で結合、同型家屋はインスタンス |
| 樹木 | 700,000 | 近景20k、中景2k、遠景400 | 距離LOD、固定シード、材質別InstancedMesh |
| 草・稲 | 200,000 | 1株3〜10 | インスタンス、近接した株のみ形状を増やす |
| 川・小物 | 100,000 | 小物3k | 繰り返し小物を結合・インスタンス |

非インデックスGLBは頂点数≒三角形数×3。インスタンスはモデルの頂点バッファを共有する。描画三角形は`renderer.info.render.triangles`（影パスを含むレンダラー計測）、呼び出し数も同APIから取得。視点・太陽・LODで変動するため、一地点の値を全マップの最大値とは呼ばない。

- 標準：DPR最大1.25、2048²の影1枚、近景LODは58m、中景190m、遠景410mまで。
- 軽量：DPR1、影なし、近景距離と遠景距離を短縮。目標65万三角形・180 calls。超過時はさらに密度を下げる。
- 高品質：DPR最大1.5、4096²の影。目標220万三角形・350 calls。
- 影は幅130mの参道・境内を対象とし、村全域の高精細な影を常時計算しない。
- 草・葉の風は軽量な頂点変位。水面はPBRとアニメーションする法線。画面空間反射、God Rays、重いBloomは未使用。
- マップ原本、配置、写真PBR、音源はローカル同梱。実行時に素材サイトへ接続しない。
- 設定から「描画情報を表示」。FPSは実際のフレーム間隔、物理は1/60秒固定。画像マップ容量の表示は推計で、全GPU使用量ではない。

最適化の順序：遠景と見えないものを減らす → 同材質を結合 → インスタンシング → LOD → テクスチャ解像度 → 影 → DPR。元モデルを無条件に削減して近景品質を落とさない。

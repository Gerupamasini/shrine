# 描画予算と計測方法

標準：デスクトップ1080p、60fps（GPU 16.7ms）、150万三角形、250 draw calls、テクスチャ256MiBを上限目安とする。これは保証値ではない。ソフトウェアWebGLの計測値から実機の60fpsを推測しない。

| 分野 | 三角形の目安 | モデル別の実測（LOD順） | 方法 |
|---|---:|---:|---|
| 地形 | 260,000 | 約256k | 集落・川は2.34375m、外周4.6875m。継ぎ目を共有する非均一格子 |
| 神社・家屋 | 280,000 | 神社36.8k/10.5k、家屋9.8–13.3k/4.4–5.4k | 75mで建築LOD、材質別インスタンス |
| 樹木・遠景樹冠 | 370,000 | 針葉樹11.9k/2.9k/988、広葉樹14.4k/4.5k/2.1k | 3段階LOD、遠景11,000本は6三角形/本のベイク画像 |
| 草・稲・シダ | 460,000 | 草15、稲5、シダ224/株 | インスタンス、草・稲は影を受けるのみ |
| 川・小物 | 130,000 | 狛犬15.6k、灯籠1.4k、鳥居880 | 材質で結合・インスタンス |

建築GLBは非インデックス、樹木GLBはインデックスあり。非インデックスGLBは頂点数≒三角形数×3。インスタンスはモデルの頂点バッファを共有する。描画三角形は`renderer.info.render.triangles`（影パスを含むレンダラー計測）、呼び出し数も同APIから取得。視点・太陽・LODで変動するため、一地点の値を全マップの最大値とは呼ばない。

- 標準：DPR最大1.25、2048²の影1枚、樹木の近景LODは32m、中景105m、遠景410mまで。
- 軽量：DPR1、影なし、樹木12/45/190m、建築38mに短縮。目標65万三角形・180 calls。草・稲・シダ・遠景樹冠の個体を全体に分散させて18%へ間引く。
- 高品質：DPR最大1.5、4096²の影。目標220万三角形・350 calls。
- 影は視点に追従する幅130mを対象とし、参道・境内・村で近景に配分する。全域の高精細な影を同時に計算しない。
- 草・葉の風は軽量な頂点変位。水面はPBRとアニメーションする法線。画面空間反射、God Rays、重いBloomは未使用。
- マップ原本、配置、写真PBR、音源はローカル同梱。実行時に素材サイトへ接続しない。
- 設定から「描画情報を表示」。FPSは実際のフレーム間隔、物理は1/60秒固定。画像マップ容量の表示は推計で、全GPU使用量ではない。

最適化の順序：遠景と見えないものを減らす → 同材質を結合 → インスタンシング → LOD → テクスチャ解像度 → 影 → DPR。元モデルを無条件に削減して近景品質を落とさない。分野別の枠は配分目安で、視点によって相互に超過・未使用が生じる。実測合計を150万以内へ調整する。中遠景のインスタンスは視錐台でも除外し、画面外から影を落とす近景モデルは保持する。

## 頂点数の実測

全GLBの頂点数・三角形数・バイト数は[`model-counts.json`](model-counts.json)に記録。`npm run assets`で再集計する。

| モデル（近景） | 頂点数 | 三角形数 |
|---|---:|---:|
| 神社 | 110,364 | 36,788 |
| 瓦屋根の民家 | 39,852 | 13,284 |
| 茅葺き民家 | 29,364 | 9,788 |
| 針葉樹 | 12,922 | 11,892 |
| 広葉樹 | 17,888 | 14,418 |
| シダ | 672 | 224 |

建築は材質別結合した非インデックスGLBのため、頂点数は三角形数の3倍。樹木のようなインデックス付きGLBと頂点数だけを直接比較しない。近景・中景・遠景の画面内個体数と影パスを合わせて描画予算を確認する。

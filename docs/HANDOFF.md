### 2026-11-18：家の壁と外観（軽量化しながら写実的に）
ユーザーの指摘「家の壁とか見た目が雑すぎて悲しい、軽量化しつつも自然さと写実的さをAAA品質ゲーム並みに」への対応。確認用画像は `artifacts/houses/`（左が変更前、右が変更後。lab-* は下の確認ページ）。
- **白壁が緑がかったまだらだった原因**：材質の色をいじるシェーダーの拡張が、2つの理由で一度も効いていなかった。①three.jsは `#include <…>` を `onBeforeCompile` の後に展開するので、チャンクの中の行（`diffuseColor *= sampledDiffuseColor;`）を置き換えても何も起きない。②カスケード影の `CSM.setupMaterial` が `onBeforeCompile` を上書きして、先に足した拡張を捨てていた。白漆喰は緑灰色の写真テクスチャ×3.9倍のまま描かれ、実効アルベドは(0.72, 0.57, 0.31)の黄土色だった。チャンクを展開してから書き換え（`library.ts`）、影の設定は前の拡張をつなぐようにした（`landscape.ts`）。
- **材質の色**：`materials.json` に `contrast`（写真の濃淡をどれだけ残すか）と `normalize`（写真を平均の色で割り、`color` を表面の平均アルベドにする）を足した。白漆喰0.6前後、モルタル0.3、下見板・柱は焦げ茶、瓦はいぶし銀、茅は麦わら色。屋根と板はこれまで実効アルベド0.01〜0.02でほぼ黒だった。
- **建物の表面のシェーダー**（`src/engine/facade.ts`、`materials.json` の `facade`）：漆喰・土壁・板・下見板・石・モルタル・桟瓦・のし瓦・トタン・茅・金物・ガラス・部屋ごとに、壁の足もとの泥はね、雨の当たる壁の雨だれ、北面のカビ、日と雨に当たる板の銀灰色化、家ごとの塗り・焼き色・汚れの違い、桟瓦の波と重なりの凹凸（法線）と1枚ずつの濃淡、トタンの瓦棒と軒先の錆、茅の古び方と苔。テクスチャは増やしていない（位置・UV・焼き込んだ遮蔽・インスタンスの位置から計算）。

- **窓の奥の部屋**（`room` 材質、インテリアマッピング）：縁側と障子・畳・襖・天井・レースのカーテン・土間を、ガラスの奥の板1枚に描く。夕方は部屋ごとに蛍光灯（青白い）か電球（暖色）が点き、障子が光る。ガラスはフレネルで空を映し、奥を透かす（`ONE, ONE_MINUS_SRC_ALPHA` の合成）。

### 2026-11-17：軽量化・運転・車種・林道・下流の谷
ユーザーの指示「めっちゃ重くなってきたので抜本的な軽量化と運転のしやすさ強化、用意した何種類かの車種の配置」「林道はいろんな山駆け巡ってていい」「下流側に平地あるのにエリア外でいけないのは渋い」への対応。
- **軽量化**：同じ6か所で、描く三角形が約半分、ドローコールが約3分の1になった（地図は2倍の広さ）。影の遠い段は大きな物だけ、建物の影は模型ごとの代役、建物は材質ごとの `BatchedMesh`、遠い地形は150mのまとめ描き、稲・下層植生・作物はタイル分けと距離で切る、遠景の木は静的バッファ、樹木と小物の更新は格子、車にLOD2、解像度の自動調整。詳しくは `docs/PERFORMANCE_BUDGET.md`。
- **運転**：キーを押すとハンドルが徐々に切れ、離すと戻る（キーボードでも細かく切れる）。速度に応じた舵角の上限（横方向約0.5G）、横滑りを抑える回転の減衰とトラクション制御、ロールを抑えるスタビライザー、低い重心。横転して止まったら1.2秒で自動で起き上がる。最高速度は軽で約70km/h、他は約80km/h（以前は減衰のため実際は約37km/hで頭打ち）。三人称カメラは車の向きだけを追い（坂で揺れない）、速度に応じて少し引いて先を見る。マウスで振り向いても走っていれば戻る。ゲームパッド（左スティックでハンドル、右トリガーでアクセル、左トリガーでブレーキ・後退、Bでブレーキ、Yで乗り降り、Xで視点）。速度計にキーの説明。運転中の車は物理エンジンで眠らない（ブレーキで止まった後に動かなくなっていた）。

- **林道**：東の尾根（奥沢側から標高98mまで、1.3km）、北の山（県道の奥沢の北から2本）、南東の山（下原から）、西の山（川向の裏を回るループと、北・南の土場への行き止まり）の9区間、計約5.2km。経路は格子の勾配を13%以下に抑えて探し（それより急だと縦断が谷の上に浮いて高い盛土になった）、道の面が地面から10m以上離れる区間は作らない。沢を越える経路は作らないので、沢の向こうへは行けない。

### 2026-11-16 後半：浮いた田の稲・はっきりした河岸段丘
ユーザーの指摘「田んぼの水面が浮いてる」「河岸段丘できてない」（PR #18 の取り込み後のスクリーンショット）への対応。
- **田の稲の縁が浮いていた**：遠景の稲は、田の水準＋0.46mの平らな面（`rice-canopy`）と、その縁に立つ稲の帯（`rice-curtain`）で描く。帯は植生マスクの青（稲の縁までの距離）から等値線で作るが、マスクを2Dキャンバスに描いて読み戻していたため、アルファ（草の密度。田の中は0）で前乗算され、田の中が「稲なし」と読まれていた。帯は約2.5万区間のうち約300区間しかできず、稲の面が泥の上に浮いた板に見えていた。PNGを自前で展開して（`src/world/data.ts` の `decodePng`）そのまま読むようにした。同じ読み方をしていた下層植生（`understory.ts`。スプラットのアルファに入っている層が0の所で、裸地・田・河原の判定が消えていた）も直った。

### 2026-11-16：急流工・川への吐口・中位段丘

### 光と見た目（前回のやり残し1）
- **木の幹が透ける**：原因は幹・枝の筒の三角形がすべて裏返し（内向き）だったこと。両面描画で表示はされていたが、法線が反転して夕日の反対側が光り、夕空を背にした幹が透けて見えた（裏面カリングのUnityでは幹が消える）。生成器（`tools/trees/build-trees.mjs`）の巻き順を直して全樹種を再生成。
- **樹冠の陰影**：葉カードの法線は樹冠の形に沿わせてあるのに、three.jsが裏面で反転していたため、半分のカードが逆に照らされていた。`CROWN_NORMALS` で反転しないようにした（遠景ビルボードの焼き込みも同じ）。

- **広葉樹の「葉の塊」**：葉アトラスの房の輪郭が滑らかな曲線で切られていたため、輪郭に葉の大きさの切れ込みを入れた（`compose_atlases.py` の `ragged_outline`）。

### 2026-11-15：川向の棚田の水（他のPRの取り込み後）
PR #15（道路と水田の接続、給水モデル `tools/world/irrigation.py`）とPR #16（谷の道路・畦）の後に、`RURAL_WATER_ACCESS.md` の残課題「西側の棚田に水源がない」を進めた。

## 再生成の手順

```sh
pip install -r requirements-assets.txt
npm ci                                    # gltf-transform は devDependencies に入った
python3 tools/world/generate_world.py     # 約2分半。浸食の結果は .cache/ に保存され、2回目以降は再利用
node tools/architecture/build.mjs --world-only   # 地形に合わせる模型だけ（全部なら引数なし）
python3 tools/world/bake_map.py
```

- 木のモデルを作り直すときは `node tools/trees/build-trees.mjs`。
- 空を作り直すときは `.cache/polyhaven/hdri/` にHDRIを置いて `python3 tools/assets/process_textures.py --sky`。
- 葉アトラスは、ベイクから作り直す場合は `compose_atlases.py` が輪郭の切れ込みまで行う。今あるアトラスに切れ込みだけを入れる `--ragged-leaf-only` は一度だけ使う（重ねると切れ込みが増える）。
- `tools/world/__pycache__/noise.cpython-313.pyc` がリポジトリに入っているため、生成後は `git checkout tools/world/__pycache__/` で戻す。

河川の設定は `generate_world.py` の `CHAN_Z0`・`CHAN_Z1`（改修区間）、`MEANDER_L`・`meander_s()`（蛇行）、`REVET`（護岸の区間）、用水は「Irrigation network」の節（川向用水は「The Kawamuko canal」、用水路の開口は `channels.png` を書く所）、林分は `STAND`、集落の性格は `HAMLETS`・`ROADSIDE_SHARE`。
